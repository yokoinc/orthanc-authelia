# TLS certificate

nginx serves the PACS over HTTPS with one of two certificates, chosen by
`SSL_MODE` in `.env`.

| `SSL_MODE` | Certificate | For |
|---|---|---|
| `selfsigned` (default) | Generated by nginx, renewed automatically | A local network; behind a Cloudflare tunnel or a proxy that does not verify it |
| `custom` | Yours: bought, issued by your organisation, or obtained elsewhere | Clients connecting directly, without a browser warning |

Behind a [Cloudflare tunnel](CLOUDFLARE_TUNNEL.md), keep `selfsigned`: Cloudflare
serves its own public certificate to visitors, the self-signed one only protects
the hop between the tunnel and nginx.

## Using your own certificate

1. Put two files in the `certs/` directory of the installation (created by
   `bootstrap.sh`, next to `.env`):

   | File | Content |
   |---|---|
   | `fullchain.pem` | the certificate, followed by the intermediate certificates of the issuer |
   | `privkey.pem` | its private key, unencrypted |

   `cert.pem` + `key.pem` are accepted too. The certificate must name the
   domain of `PUBLIC_URL`, otherwise browsers warn.

2. In `.env`:

   ```ini
   SSL_MODE=custom
   ```

3. Apply:

   ```bash
   sh scripts/apply.sh
   ```

At every start nginx checks that the key belongs to the certificate, that the
certificate has not expired, and whether it names the domain. A certificate
that fails the first two checks stops nginx with the reason in its log, rather
than falling back to a self-signed certificate nobody notices:

```bash
docker logs orthanc-nginx 2>&1 | grep -E "ERROR|WARNING|certificate"
```

Your certificate is used as it is and **never replaced**. nginx warns in its log
30 days before it expires.

## Renewing it

Replace the two files in `certs/`, then `sh scripts/apply.sh`. Nothing else.

## Checking what is served

```bash
echo | openssl s_client -connect localhost:30443 -servername pacs.example.org 2>/dev/null \
  | openssl x509 -noout -subject -issuer -enddate
```

Use the port of `PUBLIC_URL` (`HTTPS_PORT` in `.env`) and its host name.

## Going back to self-signed

`SSL_MODE=selfsigned`, then `sh scripts/apply.sh`: nginx notices the certificate
in place is not one it generated and makes a new one.

## Why no automatic Let's Encrypt

It needs port 80 open on the router permanently (for every renewal) and a
domain pointing to it. For access from the Internet the recommended setup is a
Cloudflare tunnel, which needs no open port at all; on a local network the
self-signed certificate is enough; anything in between can use `custom`.
